# Architecture
- Never use `config('mess.active_mess_id')` directly as the integer for `mess_id` columns. Use the `Mess::activeId()` helper which resolves the id at runtime from the `messes` table (with config as override only). Confidence: 0.85
- External integrations must fail open: a third-party API/network failure (e.g. Google Sheets) must never block, slow, or roll back the primary database write — the DB stays the source of truth and sync errors surface separately. Confidence: 0.6
- Prefers feature/integration setup (credentials, connection) to be configurable from the app dashboard by the user, rather than only via env/config files. Confidence: 0.55
- When a subsystem/integration is unwanted, remove it completely rather than leaving it disabled: delete the code, disk/config entries, env keys, dead DB columns, docs and stale references in one pass. Confidence: 0.6
- Wants admin/operational subsystems to be low-friction: asks for them to be "more effective and easy to manage and configure", and favours guided/automated setup (e.g. a one-click OAuth connect instead of hand-building credentials), being able to test values before saving, plain-language summaries of settings, and a single unified health/status view. Confidence: 0.5
- Wants operational misconfiguration surfaced in the UI with an actionable explanation and the exact command to run (copy-pasteable), instead of a feature silently appearing "in progress"/failing: e.g. a banner for a missing scheduler cron, and for an idle queue worker that leaves queued jobs stuck on `running`. Confidence: 0.55
