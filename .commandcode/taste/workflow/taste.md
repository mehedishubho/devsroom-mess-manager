# Workflow
- Do not assume default local DB credentials (e.g. `root`/no password) without verifying with the user. Confidence: 0.55
- Offer proactive recommendations and suggestions for project features/architecture rather than just executing on answers. Confidence: 0.60
- When pointed at a page/directory and asked to make it "more effective", expects a whole-page audit: report what each existing feature does, concrete gaps/bugs, and prioritized (highest-leverage-first) improvement suggestions — not just a summary of what exists. Confidence: 0.60
- When a UAT test fails, pause UAT, write a debug session to `.planning/debug/`, write a fix plan to `.planning/phases/{phase}/{plan}-fix-{name}.md`, then execute the fix. Confidence: 0.75
- When a UAT test cannot run due to a third-party dependency (e.g. email provider not configured, external API down), mark it as `blocked` (not `failed` or `pending`) with `blocked_by` and `reason` fields, then move to the next test. Confidence: 0.70
- Use `php artisan test` to run the test suite and `php vendor/bin/pint` for code style after making code changes. Confidence: 0.75
- Write commit messages to a temp file (e.g. `.git_commit_msg.txt`) and use `git commit -F` so multi-line messages don't get mangled by shell escaping. Confidence: 0.70
- Clean up temporary verification scripts (e.g. `verify_fix.php`, `reseed.php`) after running them. Confidence: 0.70
- Expects documentation to be updated as part of any feature/behaviour change, proactively and not only when asked — README, the deployment doc(s), setup/usage docs, `.env.example`, and the `.planning/` (STATE/PLAN/SUMMARY) artifacts. Follows up with "did you update the documents?" when it looks skipped. Confidence: 0.65
- In Copilot (VS Code), use `vscode_askquestions` wherever the GSD workflow calls `AskUserQuestion` — they are equivalent and `vscode_askquestions` is the VS Code Copilot implementation of the same interactive question API. Do not skip questioning steps because `AskUserQuestion` appears unavailable. Confidence: 0.80
- On Windows cmd (the default shell here), `head`, `grep`, and other Unix-style commands are not recognized. Use Windows equivalents: `findstr` instead of `grep`, `more` or PowerShell `Select-Object -First N` instead of `head`, or omit the pipe and read full output. Confidence: 0.80
- GSD `phase-plan-index` reports `has_summary: false` when SUMMARY files use descriptive naming like `{plan_id}-{slug}-SUMMARY.md` instead of the strict `{plan_id}-SUMMARY.md`. Verify actual completion via git log and `Self-Check: PASSED` markers before assuming a plan is incomplete. Confidence: 0.70
- When presented with a categorized list of findings/fixes (bugs, additions, per-area improvements), implement ALL of them in one batch — don't stop to ask which to do first or triage the list down. Confidence: 0.6
- The devsroom-mess-management repo currently has no test runner (tests/ and phpunit.xml were deliberately removed in quick task 260724-pm2) — do not reintroduce one; verify changes with `vendor/bin/pint --test`, `php artisan migrate`, `view:cache`, `route:list`/`schedule:list` and targeted tinker/DB checks instead. Confidence: 0.6
- When aligning docs with a change, update only the docs describing the current system (README, DEPLOYMENT, SETUP-USAGE-DEPLOY, AGENTS.md, etc.); do NOT rewrite historical/audit-trail records such as `.planning/` STATE/ROADMAP/phase docs — old mentions there are correct as history. Confidence: 0.6
- For docs that are wholesale stale (generated/derived maps like the GSD `.planning/codebase/*` codebase map), flag them for a full regeneration/re-map rather than hand-patching a handful of lines. Confidence: 0.55
