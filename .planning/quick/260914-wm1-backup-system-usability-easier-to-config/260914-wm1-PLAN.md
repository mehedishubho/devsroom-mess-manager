# Quick Task 260914-wm1 — Backup system usability: easier to configure & manage

## Goal

Remove the friction from the backup system. Configuring an off-site mirror
(especially Google Drive) is currently the hardest part of the app, and the
operational state is spread across three separate banners with no storage or
growth picture.

Operator chose the full bundle: **configure + manage**.

## Tasks

### Task 1 — Retention planner, purge preview, storage & growth, config summary

**files**
- `app/Services/BackupRetention.php` (new)
- `app/Console/Commands/PurgeBackups.php`
- `app/Http/Controllers/Backup/BackupController.php`
- `resources/views/dashboard/backups/index.blade.php`

**action**
- Extract the age + size-cap rotation decision into `BackupRetention::plan()`
  (pure function over `[path,size,ts]`). `backup:purge` consumes it so the
  preview and the enforcement **cannot drift**.
- Purge preview: "next rotation will delete N archive(s) (X MB): …" on the page.
- Per-destination usage: count, total size, oldest/newest per active disk.
- Growth: record today's local total in the cache (`backup-size:{Y-m-d}`, 30d)
  and show the delta vs ~7 days ago (null until history exists).
- Plain-language config summary line (cadence · retention · cap · mirrors).

**verify** `vendor/bin/pint --test app` · `php artisan view:cache` · tinker:
`BackupRetention::plan(...)` returns the same set the command deletes.

**done** The page states what rotation will remove, how much each destination
holds, how fast it is growing, and what the settings mean in plain English.

### Task 2 — Per-run duration + archive size in the activity log

**files**
- `database/migrations/2026_09_14_000200_add_metrics_to_backup_logs.php` (new)
- `app/Models/BackupLog.php`
- `app/Services/BackupRunner.php`
- `app/Jobs/RunBackupJob.php`
- `resources/views/dashboard/backups/index.blade.php`

**action**
- Add nullable `duration_ms` + `size_bytes` to `backup_logs`.
- `BackupRunner::run()` reports the archive it produced (path + size).
- `RunBackupJob` times the run and stores duration + size on the activity row.
- The Activity log shows e.g. `12.4s · 48.2 MB` so drift is visible.

**verify** `php artisan migrate` · `vendor/bin/pint --test app database` ·
tinker: dispatch a run and confirm the columns populate.

**done** Every completed run records how long it took and how big the archive
was.

### Task 3 — One unified health panel

**files**
- `app/Http/Controllers/Backup/BackupController.php`
- `resources/views/dashboard/backups/index.blade.php`

**action**
- Replace the separate scheduler and queue banners with a single health panel
  containing rows: **Scheduler**, **Queue worker**, **Last backup**, **Mirrors**.
- Each row: ok/attention state, a one-line detail, and the exact fix (cron line
  / worker command) with copy buttons when unhealthy.
- Keep the existing detection logic (schedulerHealth, queueHealth, lastBackupAt)
  and add mirror status (configured? reachable per destination).

**verify** `vendor/bin/pint --test app` · `php artisan view:cache` ·
`php artisan route:list --name=dashboard.backups`

**done** One glance answers "is my backup system healthy?" instead of three
banners to reconcile.

### Task 4 — Guided Google Drive OAuth, test-before-save, presets, inline help

**files**
- `app/Http/Controllers/Backup/GoogleDriveController.php` (new)
- `app/Http/Controllers/Backup/BackupController.php`
- `routes/web.php`
- `resources/views/dashboard/backups/_configure_form.blade.php`

**action**
- **Connect Google Drive**: `GET /dashboard/backups/google/redirect` builds the
  consent URL (offline access, consent prompt, `state` in session) and redirects;
  `GET .../google/callback` exchanges the code, stores the refresh token, and
  creates + stores a folder id when none is set. Uses the already-installed
  `google/apiclient`. Guarded by `role:super-admin` (route group) + a token
  exchange error path that surfaces the real message.
- **Test connection against typed values**: the form's test button POSTs the
  current credentials; empty secret boxes fall back to the stored secret.
- **Presets** (Light / Balanced / Maximum safety) that set schedule, retention
  and encryption fields client-side.
- **Inline help**: a `<details>` per provider with the exact steps to obtain the
  credentials, and the redirect URI to register.

**verify** `php artisan route:list --name=dashboard.backups` ·
`vendor/bin/pint --test app routes` · `php artisan view:cache`

**done** Connecting Google Drive is a button (no hand-built refresh token), the
credentials can be tested before saving, and both providers carry their own
setup instructions.

## Constraints

- **No test suite** — verify with pint / migrate / view:cache / route:list /
  tinker. Do not add one.
- All strings via `__()`. Tailwind v4 only. Super-admin gating + the manual
  Audit trail stay intact (new OAuth actions get audit rows).
- `config/backup.php` stays bootstrap-safe (no DB reads at config load).
- Secrets never rendered back into the DOM.
