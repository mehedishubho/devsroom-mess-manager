# Quick Task 260914-uk4 — Backups dashboard overhaul

## Goal

Make `/dashboard/backups` effective across every feature it exposes: fix the
verified bugs, close the blind spots in the activity log / backup list /
configuration surface, add the missing high-value capabilities (stats, checksums,
per-destination status, safety backup, upload-restore, queued runs with progress),
and **remove the DigitalOcean Spaces backup system entirely** (not wanted).

## Verified problems this plan fixes

| # | Problem | Evidence |
|---|---------|----------|
| B1 | `backup:purge` never writes a `BackupLog` row | `PurgeBackups::handle()` has no log write; spatie `Cleanup*` events only fire from `backup:clean`, which is not scheduled |
| B2 | UI delete is local-only | `BackupController::destroy()` → `backupDisk()`; `PurgeBackups` fans out over `BackupDestinations::all()` |
| B3 | Nightly `monitor/success` spam buries failures | `LogScheduledBackupActivity` maps `HealthyBackupWasFound` → row, every night at 02:00 |
| B4 | Log deletion is not audited | `destroyLog()` / `clearLogs()` write no Audit row, unlike download/delete/restore |
| B5 | Restore runs inline in the HTTP request | `RestoreController::store()` → `BackupRestoreService` (down → mysql 600s → up). A gateway kill can skip `finally` and strand maintenance mode |
| B6 | No pre-restore snapshot | A bad restore is unrecoverable from the UI |
| B7 | No restore from an uploaded archive | Disaster recovery on a fresh server has no path in |
| B8 | `backup_logs` grows unbounded | No pruning anywhere |
| B9 | Dead `enabled_spaces` column | Never read/written |
| B10 | Saved secrets cannot be cleared | `update()` treats empty as "keep" |

**done** Purge is visible on the Activity log; deleting a backup removes it from every active disk; monitor rows no longer bury failures; log delete/clear are audited; log table is pruned on a schedule.
